# COMEEGA Authorship

**COMEEGA** — *Collaborative Org-Mode Enhanced Emacs Generalized Authorship* —
is the standard authorship model for BISOS source in every language BISOS
uses. In COMEEGA:

1. Org-mode content is embedded inside each language's *comment-block* or
   *docstring* syntax. The result is a "surrounded program": traditional
   source code with a parallel human-oriented org-mode view of headings,
   TODOs, tables, links, and cross-references.
2. Org-mode *dynamic blocks* are extended to non-org files. A dblock is a
   `####+BEGIN: <signature> [:key value ...]` / `####+END:` pair whose
   body is regenerated by a handler (elisp or Python).

COMEEGA can be thought of as the inverse of literate programming: literate
programming embeds code inside prose; COMEEGA embeds prose inside code.

## The one universal rule

**Never hand-edit content between `####+BEGIN:` and `####+END:` markers.**
That content is generated. Author only:

1. The `####+BEGIN:` header line (signature + `:key value` pairs).
2. The body *after* the `####+END:` marker.

If a dblock body looks wrong, update the `####+BEGIN:` header parameters or
regenerate — don't patch the generated content.

**Regeneration.** Inside Blee/Emacs: `M-x org-dblock-update`. Outside Blee:
`py-dblock.cs updateDblocks <file>` from `bisos.pyDblock` (pure Python, no
Emacs required — used by `aiActivity.cs initiate` and by `pypiProc.sh` for
`setup.py`, `pyproject.toml`, etc.).

## Per-language comment / docstring / dblock syntax

| Language      | Major mode        | Org-comment-block   | Org-docstring         | Dynamic block prefix           |
|---------------|-------------------|---------------------|-----------------------|--------------------------------|
| Python        | `python-mode`     | `""" #+begin_org ... #+end_org """` triple-quoted string | `""" #+begin_org ... #+end_org """` docstring | `####+BEGIN: ... ####+END:` |
| Elisp         | `emacs-lisp-mode` | `(orgCmntBegin ... orgCmntEnd)` via `comment-block` pkg | `" #+org_begin ... #+org_end "` string | `####+BEGIN: ... ####+END:` |
| Bash          | `sh-mode`         | Here-document construct    | (same)                  | `####+BEGIN: ... ####+END:`    |
| LaTeX         | `latex-mode`      | `\begin{comment} ... \end{comment}` via LaTeX `comment` pkg | (same)  | `####+BEGIN: ... ####+END:`    |
| HTML          | `html-mode`       | *(stub — TO BE DOCUMENTED in canonical README)* | *(stub)*        | *(stub)*                       |

The `####+BEGIN:` / `####+END:` dblock prefix is uniform across all
languages — it's the *body* that's language-specific. In Python, dblocks
appear directly in the file because `####...` is a Python comment. In
elisp, dblocks appear inside `(comment-block ... )`. In bash, they appear
inside here-documents. Same signature, same regeneration machinery.

## The BISOS Python file header — concrete recipe

For BISOS Python source (`.cs`, `.spcs`, `_csu.py`, `_seed.py`,
`_seedInfo.py`), every file opens with a standardized dblock header chain.
Ordered:

1. **File-level Summary docstring** — one-line summary in
   `""" #+begin_org * ~[Summary]~ :: ... #+end_org """`.
2. **`b:py3:cs:file/dblockControls :classification "<cls>"`** — where
   `<cls>` is one of:
   - `cs-mu` — CS multi-unit executable (a `.cs` csxu entry point)
   - `cs-u`  — CS unit executable (a `.cs` with no CSU imports)
   - `cs-lib` — CS library (a `_csu.py` module)
   - `bpf-lib` — BPF library (pure Python module)
   - `pyLibPure` — pure Python library, no CS framework dependency
3. **`b:prog:file/proclamations :outLevel 1`** — AGPL + BISOS + Poly-COMEEGA proclamation.
4. **`b:prog:file/particulars :authors (...)`** — authors, file paths.
5. **`b:py3:file/particulars-csInfo :status "..."`** — the `csInfo` dict
   (version, status, panel, groupingType, cmndParts).
6. *Free-form description* (in `""" #+begin_org ... #+end_org """`) — module description.
7. **`b:prog:file/orgTopControls :outLevel 1`** — org navigation.
8. **`b:py3:file/workbench :outLevel 1`** — Blee workbench links.
9. **`b:py3:cs:framework/imports :basedOn "classification"`** — standard imports.
10. **`b:py3:cs:framework/exceptionImports`** — enhancedExceptions.
11. *(For csxu `.cs` files with plants)* **`b:py3:cs:framework/csxuSeeded`** — imports `plantedCsu`.
12. *(For csxu `.cs` files)* elisp `b:py:cs:csuList` block + **`b:py3:cs:framework/csuListProc`** — imports all CSUs.
13. Section dividers via **`blee:bxPanel:foldingSection`**.
14. For each `cs.Cmnd`: **`b:py3:cs:cmnd/classHead`** — see `writing-cs-commands`.
15. **`b:py3:cs:framework/main`** — the `if __name__ == '__main__':` block.
16. **`b:py3:cs:framework/endOfFile`** — end-of-editable-text marker + emacs locals.

The full recipe with example bodies is in the `bisos-pip-setup-py` skill.

## Cross-language notes

COMEEGA is not language-specific but BISOS's mature COMEEGA usage is
strongest in Python (via the `bisos.pyDblock` regeneration engine).
For other languages:

- **Elisp** — Blee's own source is authored in Poly-COMEEGA. The
  `comment-block` elisp package provides block comments (elisp itself has
  only line comments).
- **Bash** — BISOS ICM (Interactive Command Module) scripts under
  `/bisos/core/bsip/bin/` use COMEEGA. Here-documents provide block
  comments; the `bx-dblock` bash entry point regenerates dblocks in
  `setup.py`, `pyproject.toml`, etc.
- **LaTeX** — the LCNT (Libre Content) framework at
  `/bisos/core/lcnt/bin/` uses COMEEGA for content authorship. The LaTeX
  `comment` package provides block comments.
- **HTML** — stub; see the canonical README for the current state.

## What NOT to do

- Do NOT hand-edit content between `####+BEGIN:` and `####+END:` — regenerate.
- Do NOT strip the proclamation, particulars, or csInfo dblocks to "clean up"
  a file — they're required for Blee/BISOS tooling to recognize the file.
- Do NOT invent a new file structure that omits the standard header chain —
  copy from a canonical reference file (see below) and adapt.
- Do NOT hand-author a `cs.Cmnd` class without the `b:py3:cs:cmnd/classHead`
  dblock — even when you write the fully-expanded form, the `####+BEGIN:`
  header line must be present so Blee can regenerate it later.
